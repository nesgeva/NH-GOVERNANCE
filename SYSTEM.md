# N.H

This specification does not authorize runtime changes.

## Purpose

N.H is Ness's local, offline-first memory and meaning system. It preserves, reads and connects sources to help him understand, create, rehearse and act. Ness decides what to believe and do. Interpretation never becomes established fact.

## Governing rules

- Preserve originals. Add interpretations beside them. Keep current views and history separate.
- Mechanical components store, carry, link, sort and gather. They establish machine state/provenance, never meaning.
- Interpretive components produce dated, grounded, confidence-tagged, rejectable readings. Firmness never changes interpretation into fact.
- Keep observed, reported, inferred, assumed, unknown, and simulated material distinguishable. Acceptance, certainty, grounding, relevance, currentness, identity, and permission are separate judgments.
- Preserve each person's perspective. N.H's own view is a revisable note, never another person's telling or a truth verdict.
- Repetition, display, retrieval, model confidence, logs, and derivative records add no independent evidence.
- Run routine reading and linking automatically within permissions. Ness steers and corrects. Do not make him approve every reading or file every memory.
- State gaps without forcing an answer. Missing information alone is neither failure nor evidence of absence.
- Keep structure as broad and deep as Ness can use. Do not grow an unlimited classification system.
- Growth belongs in memory. Do not train the base model or store N.H's identity in model weights.
- Keep data local unless a connector and its specific use are authorized. A network connection alone grants no authority.

## Components

| Owner | Responsibility |
|---|---|
| Catalog | Capture, provenance, eligibility, blockers, source grouping, root-ingestion handoff |
| Root store | Immutable source records, distinct sealed batches, append validation |
| Meaning Engine | One combined contextual reading pass and provisional creation detection |
| Acceptance machinery | Independent assessment of proposals and recorded outcomes |
| Context Retrieval | Separately labeled positional and semantic context |
| Story Layer | Source-grounded tellings, perspectives, firmness, themes |
| Person-Boxes | Identity anchors and reference collections, never personality summaries |
| Living State Web | Evidence-linked state episodes, relationships, hypotheses, world conditions |
| Computed View | Inspectable current presentation over preserved records |
| Relevance control | Purpose-specific gates and dimensions |
| LMAC | Stateless routing to current owner data during a function |
| BOP / OOP | Authorized physical observations and outcomes through Catalog |
| Privacy / SACL / BAI | Privacy decisions, speaker access, purpose-bound biometric proofs |
| Action authority | Suggestions, preparation, exact execution permission, results |
| Wonder / interface | Explicit simulation and presentation over references |
| AIC / UDOK | Artifact-authority verification and durable operation coordination |

Owners retain their decisions, records, keys and effects. Routers, coordinators, indexes, interfaces and models cannot assume another owner's authority.

LMAC cannot filter, summarize or cache owner data. Privacy and rule-authority queries obtain the required decisions through a metadata-only control path, without recursively requiring those same decisions first. It queries stored BOP/OOP observations through their owners, never the physical processors. Transport retries keep one logical query identity and terminal outcome.

BOP's optional `acoustic_condition_notes` describe the recording only. Each note requires `condition_name`, `detection_method`, `detection_version`, `threshold_value`, `measured_value` and `certainty`. Names are `high_ambient_noise`, `close_microphone`, `far_microphone`, `room_reverb_present` and `signal_compression_heavy`. Certainty concerns detection. Absence proves nothing. Notes alone establish no identity, spoofing, emotion, intent or meaning. Consumers may use them as provenance-bearing physical context under their own rules. Methods, thresholds and calibration remain open.

## Main path

1. Capture material/provenance; exclude protected content before ordinary storage.
2. Catalog resolves metadata/blockers. Do not interpret held material ordinarily.
3. The shared writer commits one root per capture to an authorized active batch.
4. Durably enqueue reading after root commitment; ingestion does not wait for models.
5. Commit pass instructions; retrieve current authorized context through LMAC.
6. Independently validate one proposal; append accepted readings to quarantine.
7. Complete required telling sets, clashes and views without duplicate effects.
8. Form permitted output; apply privacy, speaker access and immediate pre-delivery revalidation.

Capture, background reading, replies, cancellation and recovery still need joint design/testing. No complete runtime cycle is claimed.

## Models

- Retrieve before wording. Embedding and language models have distinct jobs.
- Engine A reads the bare root. Engine B uses up to three complete immediately preceding same-thread turns. Keep `BACKGROUND` / `END BACKGROUND` framing. Do not replace this experiment's positional retrieval with semantic search or apply its limit universally.
- Engine B interprets the target only. It must not quote or paraphrase background as if the target said it. Gold v1 and v2-B do not grade Story Layer output. Several grounded readings can be valid.
- Interpret the speaker's act; do not answer/continue the source conversation. Resolve what short confirmations confirm.
- Final models remain undecided. Historical tests used `dolphin-llama3` 8B and `all-MiniLM-L6-v2`. Dolphin 3.0 R1 Mistral 24B is a selected testing candidate, not an adopted model. RTX 3090 is the recorded hardware direction, not proof of purchase, installation or adequate performance.
- Benchmark replacements against both sealed gold sets and applicable story/dual-model cases. Verify exact model, quantization, license, resource use, and throughput. Ness adopts a replacement explicitly. Passing tests neither installs it nor triggers mass rereading.
- Provider refusals describe model limits, not N.H policy, Ness's restrictions or source truth. Preserve low-restriction, auditable local operation.

## Dual-model conversation

The accepted direction uses a heavy analyst and a light conversational messenger as one N.H personality.

- Capture each new contribution immutably. Commit routing separately. One contribution has at most one owning deep-answer operation.
- During analysis, the messenger may acknowledge clear content, ask one bounded clarification, gather relevant information or report progress. It cannot invent the deep answer.
- Preserve message order and bind work to its request revision. Commit whether new information leaves analysis unchanged, supplements it, or requires cancellation and restart. Added requirements trigger checks of affected work; changed premises require reconsideration. Reuse verified facts only where still applicable. Do not relabel old work or create a new parent automatically for each turn. If impact is unclear, ask one focused question while independent work continues. Acknowledgment cannot imply completed reanalysis.
- Cancellation may finish late. An earlier brief needs explicit compatibility assessment and current validation before use under the new request revision. That assessment cannot rebind stale owner records or bypass SECURITY.md's delivery checks. Stop remaining outdated speech, explain the change within current permissions, and prepare the revised answer.
- The analyst produces an immutable structured brief. Validation records remain separate.
- Use MEMORY.md's acceptance responsibilities and OPERATIONS.md's reviewer tests, alongside independence checks and required external adjudication. See DECISIONS.md for remaining choices.
- Messenger briefs exclude private reasoning, rejected substance, unnecessary protected material, full evidence locators and model confidence scores.
- Validate the messenger's semantic fidelity. Preserve uncertainty and speaker agency across English, Hebrew, and other languages. Failed or stale drafts never reach delivery.
- Failure stays explicit. Do not surface partial or unvalidated conclusions as the answer. A child's failure does not automatically terminate its parent.

Capture and routing are separate committed records. Freeze the routing plan before effects or completion. Record whether a supplement was actually applied and acknowledged, cancelled, restarted or remains unknown. Never infer receipt from dispatch. A validated minimal messenger fallback may state only approved facts, scope, unknowns and explicitly unconfirmed possibilities. It still passes delivery gates. This is separate from B24's insufficient-context fallback in MEMORY.md.

Concurrent deep topics may finish independently while conversation continues. Resource limits and backpressure still apply. This direction does not add workers to the single-worker reading queue or settle topic presentation.

Ness approved the candor direction for ordinary instructions and inference-time steering without training. Preserve disagreement, inconvenient details and unknowns without flattery changing substance. The complete strategy package remains unadopted; fine-tuning, exact controls, tolerances and activation remain open. No promise of zero fabrication or extra validation authority follows.

## Framework directions

Ness approved the directions for Authority Integrity, UDOK, provenance-first Memory Fabric, a bounded repair laboratory and a governed capability registry/tool forge. Direction approval does not accept every proposed mechanism or activate a framework. OPERATIONS.md owns accepted AIC/UDOK boundaries. EXPERIENCE.md preserves the other directions and their candidate mechanics.

An unchanged model has not acquired independent thought or a new kind of cognition merely because memory and tools surround it. Classification breadth and depth stay within the deliberately chosen usable boundary; enlargement needs a deliberate change.

## Verification and status

These are design records, not runtime code. Verify runtime files before relying on historical claims of 5,521 sealed roots, Engines A/B, quarantine, two gold sets and a Chroma index.

- Gold v1 has eight bare-root cases. Gold v2-B has seven context cases. Historical A/B scores are observations, not promised future results.
- Ness judges semantic results. Fabrication fails. Grounded omission alone does not fail. Correct additional content may pass. Model self-assessment cannot grade its own output.
- Keep gold sets sealed. Corrections create a new version. Engine C requires available, pinned story-bearing cases before testing. A design closure cannot supply missing case bytes.
- Preserve the legacy REALITY/SIMULATION gate and its promotion protections until explicitly decommissioned. Do not treat a newer design as a completed migration.
- Design approval, artifact acceptance, implementation permission, test success, and production activation are separate events.
- The existing route pauses building until the genuine gaps and final system description are complete and Ness authorizes building. This documentation refactor does not resume runtime development.
