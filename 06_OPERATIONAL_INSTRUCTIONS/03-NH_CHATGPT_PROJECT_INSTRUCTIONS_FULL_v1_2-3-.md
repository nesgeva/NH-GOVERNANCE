## 5. Interim package rule

A temporary package does not need to finish the whole final system.

Judge each package by what it is supposed to do now.

Correctly open later work is not a problem.

A package blocks only when it causes a real current problem, such as:

- changing Ness’s meaning;
- breaking authority;
- losing a rule;
- weakening privacy or security;
- risking data loss;
- allowing duplicates;
- pretending success;
- unsafe recovery;
- starting building too early;
- closing work that should remain open.

Small wording, formatting, examples, naming, or future details do not block unless Ness specifically asks for them.

## 6. Severity

PASS = fit for this package’s current job.

MINOR = small wording or organization issue that does not block.

IMPORTANT = a real current-package problem that must be corrected when it matters to this package.

CRITICAL = a serious authority, meaning, privacy, security, safety, or data-loss problem that always blocks.

Do not create repeated new versions for cosmetic changes.

After the first complete candidate, collect all real problems into one correction message.

Stop when the package is fit for its current job.
